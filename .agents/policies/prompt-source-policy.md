# Prompt Source Policy

## Purpose
Keep this framework project-owned and vendor-neutral while still learning from
public agent prompt ecosystems.

## Rules
- Public prompt repositories may be studied for architecture, decomposition, and
  behavioral patterns.
- Do not copy proprietary, leaked, extracted, or vendor system prompts verbatim.
- Rewrite all guidance in project-owned, vendor-neutral language.
- Prefer reusable concepts over vendor phrasing:
  - role separation
  - tool discipline
  - verification loops
  - memory policy
  - failure handling
  - prompt packs
  - evals
- Record source inspirations only at a high level. Cite the repository or idea,
  not copied text blocks.

## Project Application
- Primary architectural inspiration: public modular prompt repos with separate
  roles, tool policies, and evaluation surfaces.
- Secondary background sources may inform cautionary patterns, but they must not
  shape wording more strongly than project-owned policy.
